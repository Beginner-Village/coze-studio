# 策略功能演示脚本 — 对公智能运营助手

**演示时长：约 10 分钟 | 面向：银行对公业务决策层及业务负责人**

---

## 一、一句话价值主张

> **"给 Agent 的不是工具列表，而是一张地图——用到哪块，才展开哪块。"**

传统做法把 30 个能力的说明全部塞进提示词，Agent 上下文臃肿、推理变慢、容易走偏；  
或者逐一绑定 30 个工具，工具爆炸、调用混乱。  
**策略（Strategy）用分层缓存 / 渐进披露解决这个问题：**  
- L1 常驻：只给 Agent 3 个超短工具名——`scenes`、`caps`、`run`  
- L2 按需发现：Agent 先问"有哪些场景"，再缩进"这个场景有哪些能力"，最后才执行  
- 结果：上下文精简、调用精准、能力再多也不增加底层噪音  

一个好的 Agent，是它所服务业务分布的忠实压缩——策略就是这个压缩机制的实现。

### 第 3 步：关键演示——Agent 自主调用，给出精准答案

**在对话框输入以下自然问题（不提工具名，不提场景名）：**

> "我有个客户要办对公开户，需要准备哪些材料？另外合规上有什么需要特别注意的？"

**观察 Agent 的调用链（请展示工具调用过程）：**

```
Agent 思考 → 调用 scenes() → 获取 5 个场景列表
        → 识别「对公开户」和「合规与风控」两个场景相关
        → 调用 caps("对公开户") → 获取 6 个能力列表
        → 判断「开户材料清单」最匹配
        → 调用 run("对公开户", "开户材料清单") → 获取完整材料清单
        → 调用 caps("合规与风控") → 识别「反洗钱客户尽职调查」相关
        → 调用 run("合规与风控", "反洗钱客户尽职调查") → 获取合规注意事项
        → 整合两段内容，输出结构化回答
```

**口述解说（调用过程中）：** "注意，Agent 没有收到任何指令说'去用哪个工具'——它自己判断这个问题涉及开户和合规两个维度，主动调了两次场景、两次能力，只取了它需要的那两个能力的内容。其余 28 个能力的文本，这次对话完全没有碰过。"

### 第 4 步：对比话术——"没有策略会怎样？"

**说话要点（无需切页面，语言对比即可）：**

> "如果没有策略，有两条路，都有问题：
> 
> **路线 A：把 30 个能力全塞进系统提示词。**  
> 上下文暴增，每次对话都要携带几千字的说明，Token 消耗大、推理变慢，而且大段文本里 Agent 找答案容易张冠李戴。
> 
> **路线 B：绑定 30 个工具。**  
> 工具列表爆炸，Agent 选择困难，工具名相近时极易混淆，调试几乎不可能。
> 
> **策略的方式：** 3 个超短工具，按需展开，像查目录一样——先翻章节，再翻页，最后读那一段。上下文始终干净。"

## 四、价值总结话术（收尾 1 分钟）

> "我们把这个设计叫做**渐进披露**：
>
> - **上下文精简**：Agent 的常驻提示词里只有 3 个工具，而不是 30 段说明
> - **更快**：工具名极短（`scenes`/`caps`/`run`），调用决策消耗 Token 少
> - **更准**：Agent 只读它真正需要的能力内容，不被无关信息干扰
> - **可扩展**：业务场景增加新能力，直接在策略里加就好，不影响 Agent 提示词，零停机更新
>
> 对公业务场景复杂、能力众多，正是最适合用策略来管理的场景。今天展示的只是 30 个能力，实际部署中可以扩展到 100+，Agent 行为不会因此变差，反而会更精准。"

## 六、应急预案

### Agent 没有主动调工具，直接给了通用回答？

**引导话术：**
> "你刚才给的是通用建议，我们有专门的业务能力库，用你的能力查一下更准确的答案。"

Agent 收到这个暗示后，通常会重新触发 `scenes` 调用。若仍不调用，检查：
1. 确认策略已正确绑定（编排页右侧工具区显示该策略）
2. 确认 Agent 的系统提示词中有引导使用策略工具的说明
3. 追问更具体的问题（如"用 scenes 工具看看有哪些场景"）作为保底

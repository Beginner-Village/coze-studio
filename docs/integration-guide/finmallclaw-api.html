外部系统集成指南

用 API 对接 finmallclaw 智能体

发一条消息 → 智能体思考、调用工具（含隔离沙箱里执行命令）→ 拿回答。全套走标准 HTTP + Bearer 鉴权，服务端一次请求即可集成。

本页所有请求 / 响应 / 事件已在 226 环境用真实 PAT 端到端跑通

三步接入

1

拿一个 API Key

在平台生成个人访问令牌（PAT）。

Bearer pat_xxx
2

建会话

最小可用示例（同步）

shell
# 变量
BASE=http://10.10.10.226:8896
PAT=pat_xxxxxxxxxxxxxxxx          # 你的 API Key
AGENT=7540939700521926656          # finmallclaw 智能体 ID
SPACE=7532755646102372352          # 所属空间 ID

# 1) 建会话，取出 conversation_id
CONV=$(curl -s -X POST "$BASE/api/super-agent/sessions/create" \
  -H "Authorization: Bearer $PAT" -H 'Content-Type: application/json' \
  -d "{\"agent_id\":\"$AGENT\",\"space_id\":\"$SPACE\"}" \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["session"]["conversation_id"])')

# 2) 发消息（同步阻塞，直接返回完整回答）
curl -s -X POST "$BASE/api/super-agent/runs/create" \
  -H "Authorization: Bearer $PAT" -H 'Content-Type: application/json' \
  -d "{\"agent_id\":\"$AGENT\",\"space_id\":\"$SPACE\",\"conversation_id\":\"$CONV\",\"user_id\":\"ext-user-1\",\"additional_messages\":[{\"role\":\"user\",\"content\":\"你好\",\"content_type\":\"text\"}]}"

1鉴权 · 获取 API Key（PAT）

对外接口用个人访问令牌（PAT）做 Bearer 鉴权。PAT 归属某个平台用户，只能调用该用户有权限的智能体——平台已按资源做 owner 校验，越权会被拒。

方式一 · 平台 UI 生成（推荐）

登录平台 → 头像 / 设置 → API 授权 / 个人访问令牌 → 新建，复制形如 pat_xxx 的令牌。明文只在创建时返回一次，请妥善保存。

方式二 · 接口生成（需登录态 Cookie）

shell
# a) 登录拿 session cookie
curl -s -c cookies.txt -X POST "$BASE/api/passport/web/email/login/" \
  -H 'Content-Type: application/json' \
  -d '{"email":"<账号邮箱>","password":"<密码>"}'

# b) 用 cookie 创建 PAT（expire_at 为到期 Unix 秒）
EXP=$(( $(date +%s) + 30*24*3600 ))
curl -s -b cookies.txt -X POST \
  "$BASE/api/permission_api/pat/create_personal_access_token_and_permission" \
  -H 'Content-Type: application/json' \
  -d "{\"name\":\"finmallclaw-integration\",\"expire_at\":$EXP,\"duration_day\":\"30\"}"
# 返回 data.token 即 PAT 明文

为对接方单独建 PAT、设合理有效期，不要把 PAT 写进代码仓库或前端。泄露后到令牌管理页删除即可失效。

2定位对接参数

参数含义怎么拿
agent_idfinmallclaw 智能体 ID（雪花 ID，字符串）智能体编辑/详情页 URL 里的 id；或平台侧提供
space_id智能体所属空间 ID详情页 URL 中的 space id；或平台侧提供
user_id对接方自定义的终端用户标识任意字符串（如 ext-user-1001），用于区分不同终端用户的会话与记忆；不传则默认 api-user-<PAT用户ID>

agent_id 与 bot_id 二选一即可（含义相同，后者为兼容字段）。

关于「超级体」：用 PAT 调 /api/super-agent/runs/* 时，后端会自动把该智能体按超级智能体 harness 运行（注入 super_agent_app_server=true 标记）——无需在数据库里把它标成 super，也无需自己传该标记。

发消息 · 同步

POST/api/super-agent/runs/create

一次请求阻塞直到回答完毕，返回体直接带完整消息列表。适合服务端后台集成，最省事。

请求体

字段必填说明
agent_id / bot_id二选一智能体 ID
conversation_id建议会话 ID；不传则单轮、无上下文
space_id建议空间 ID
user_id建议终端用户标识
additional_messages是本轮用户消息数组，元素 {"role":"user","content":"…","content_type":"text"}
custom_variables否提示词变量（JSON）
meta_data否透传业务元数据

响应（实测 · 截断）

json · 200
{
  "code":0, "msg":"success",
  "conversation_id":"7659722823681703936",
  "bot_id":"7540939700521926656",
  "status":"completed",
  "messages":[
    {"role":"assistant","type":"function_call", "content":"{…run_bash…}"},
    {"role":"assistant","type":"tool_response","content":"exit_code: 0\nstdout:\n…"},
    {"role":"assistant","type":"answer",       "content":"最终回答文本"},  // ← 取这条
    {"role":"assistant","type":"verbose",      "content":"{…generate_answer_finish…}"}
  ]
}

取最终回答：遍历 messages，取 type == "answer" 的 content。中间的 function_call / tool_response 是工具调用轨迹（如沙箱命令执行），审计或展示时可用。

发消息 · 流式（SSE）

POST/api/super-agent/runs/stream

请求体同「同步」。响应为 text/event-stream，按事件实时推送。适合前端打字机效果、实时展示工具执行。

事件序列（实测）

event-stream
event:conversation.chat.created        # 本轮 run 创建
event:conversation.chat.in_progress    # 开始处理
event:conversation.ack                 # 已收到用户消息（回显）
event:conversation.message.delta       # 回答增量（多条，逐字/逐段）
event:conversation.message.completed   # 一条完整消息（answer / function_call / tool_response / verbose）
event:conversation.chat.completed      # 本轮结束
event:conversation.stream.done         # 流结束，收到即可关闭连接

每个 data: 是一段 JSON。用 message.completed 的 type 区分内容类型，见 SSE 事件与消息类型。

shell · curl -N
curl -sN -X POST "$BASE/api/super-agent/runs/stream" \
  -H "Authorization: Bearer $PAT" -H 'Content-Type: application/json' \
  -d '{"agent_id":"'$AGENT'","space_id":"'$SPACE'","conversation_id":"'$CONV'",
       "user_id":"ext-user-1",
       "additional_messages":[{"role":"user","content":"帮我算 1+1","content_type":"text"}]}'

多轮对话 与 历史

用同一个 conversation_id 反复调「同步」或「流式」接口即可，平台自动维护上下文与记忆。（另有 POST /api/super-agent/runs/reply 语义等价，conversation_id 必填。）

POST/api/super-agent/messages/list

拉取会话历史消息。

字段必填说明
conversation_id是会话 ID
limit否每页条数（≤100）
order_by否ASC / DESC
before_id / after_id否游标翻页

返回 data.messages（或 message_list）为消息数组，含 role / type / content。

取消运行

POST/api/super-agent/runs/cancel

中断一次进行中的流式运行。请求体带 run_id（或 conversation_id）。

沙箱能力

finmallclaw 这类超级体可以在隔离沙箱容器里执行命令、读写文件（工具 run_bash、write_file 等）。是否给某次运行挂载沙箱工具，满足下面任一条件即挂载：

  1. 后端环境变量 SANDBOX_TOOLS_ENABLED=true（全局强制开启）；或
  2. 该智能体绑定了至少一个技能（Skill）。

平台侧前置条件（226 已就绪）

  • 后端 SANDBOX_ENABLED=true（沙箱总开关，2026-07-07 已在 226 重新开启）；
  • 后端容器挂载了 /var/run/docker.sock，本机存在沙箱基础镜像 ynet-sandbox:rich。

运行时每个智能体会话拉起一个独立沙箱容器，命名形如 ynet-sb-a<agentId>-<hash>，空闲后自动回收。

若调用后智能体回复「无法在沙箱中执行命令」，说明该智能体没绑技能且未开全局 SANDBOX_TOOLS_ENABLED，此时它只做纯对话——给它绑定一个技能即可获得沙箱执行能力。

SSE 事件与消息类型

全部事件类型

conversation.ack conversation.chat.created conversation.chat.in_progress conversation.message.delta conversation.message.completed conversation.chat.completed conversation.chat.failed conversation.chat.cancelled conversation.stream.done conversation.error

结束事件 conversation.stream.done；错误事件 conversation.error 或 conversation.chat.failed。

message.completed 的 type

type含义
ack用户输入回显
function_call智能体决定调用某工具（如 run_bash），content 内含工具名与参数
tool_response工具返回（如沙箱 exit_code / stdout / stderr），meta_data.time_cost 为耗时秒数
answer面向用户的最终回答文本
verbose内部状态标记（如 generate_answer_finish），可忽略

错误处理

情况表现 / 处理
成功HTTP 200 且 code == 0
业务错误code != 0，msg 为原因
鉴权失败401 / ErrUserAuthenticationFailed：Authorization 头缺失或 PAT 无效/过期
越权调了非本 PAT 用户拥有的智能体 → 权限错误
流式出错收到 conversation.error 或 conversation.chat.failed 事件
model not found目标空间未绑定模型，需在平台为该空间配置可用模型

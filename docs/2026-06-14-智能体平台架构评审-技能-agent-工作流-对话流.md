# 智能体平台架构评审：技能 / 单智能体 / 工作流 / 对话流

> 日期：2026-06-14
> 方法：4 个并行子 agent 通读 backend 对应子系统源码，全部结论带 `文件:行` 依据。
> 范围：现状盘点 + 问题 + 优化方向（不含实现）。

---

## 0. 一句话结论

四块整体架构选型合理（都建在 eino 之上，复用度高），但各有明确的债务。**最紧急且唯一的"崩溃级"问题在工作流的 `ExecuteConfig` 锁按值拷贝**（并发下会 `concurrent map` 直接 crash）；其次是几个**正确性 bug**（技能 plugin/knowledge 引用是死路、对话历史会读进软删消息）；再次是**能力没接通**（自主规划 `update_plan` 挂了却没人用）和**成本/上下文治理缺失**（全程无 token 维度裁剪）。

## 1. 🔴 P0 — 必须先修（崩溃级）

### 1.1 工作流 `ExecuteConfig` 含 `sync.RWMutex` 被全链路按值拷贝
- 根源：`api/model/crossdomain/workflow/workflow.go:77` 把 **值类型** `hiAgentConversationsMu sync.RWMutex` 直接内嵌进 `ExecuteConfig`，保护 map `HiAgentConversations`。
- `go vet` 实测 **40+ 处 lock-copy**，关键点：`crossdomain/impl/workflow/workflow.go:61/65/69/72`、`compose/workflow_run.go:97`、`nodes/llm/llm.go:1136-1137`、`nodes/plugin/plugin.go:117/122` 等。
- 风险：锁被值拷贝 → 副本是另一把锁 → 锁失效 → ChatFlow/Batch 并发/LLM 并发工具调用下 **`fatal error: concurrent map read and map write` 直接崩进程**；并放大每节点拷贝开销。
- 修法（推荐低成本方案）：把 `HiAgentConversations` + 锁抽成独立 `*HiAgentConvStore`（指针内含锁），`ExecuteConfig` 恢复为可安全值拷贝的纯数据；或全链路改 `*ExecuteConfig`。改完 `go vet ./domain/workflow/... ./crossdomain/...` 应清零。
- 附带：删除过时的第二份定义 `domain/workflow/entity/vo/execution.go:28`，避免两套 drift。

## 2. 🟠 P1 — 正确性 Bug（数据/行为错误）

### 2.1 对话历史会把"软删除"的消息喂给模型
- `message/internal/dal/message.go:128` `GetByRunIDs` **缺 `status=available` 过滤**（对比 `List` :76 有）。Regenerate 只软删消息，但历史构造走 `GetByRunIDs` → 已删消息仍进 LLM 上下文。一行即可修。

### 2.2 技能的 plugin/knowledge 资源引用是"死路"
- `node_tool_skill_resources.go:96` 显式 `if ref.ResourceType != "workflow" { continue }` → **只有 workflow 会被运行时挂载**；plugin/knowledge 引用在 `read_skill` 里只被替换成一段"请用对应工具"的提示文字（`node_tool_skill.go:218-221`），但那个工具根本没挂 → 模型"幻觉调用"。

### 2.3 技能无 spaceID 越权校验
- `readSkillTool` 存了 `spaceID` 却从不使用（`node_tool_skill.go:41,52`）；`loadSkill→GetSkill` 按 id 查库不校验 space（`node_tool_skill.go:168`）。应改用 `GetSkillByName(spaceID,name)` 或显式校验。

### 2.4 技能 `status` 字段形同虚设
- 表有 `status default 1`，但 Get/List/MGet 全不带 status 条件（`skill_dao.go:140-194`）→ 无法停用技能。

## 3. 🟡 P2 — 能力没接通 / 自主规划（高价值、低成本）

### 3.1 `update_plan`「挂了但没人用」
- 工具已实现（`node_tool_sandbox.go:207-260`），但：(1) 仅在 `sandboxToolsEnabled()`（绑了技能或 env 开关）时挂载，绝大多数 agent 没有；(2) **主提示词里没有任何"复杂任务先 update_plan 拆解再执行"的指令**（`system_prompt.go:29-80`），模型不知道该调它 → 自主规划停留在纸面。
- 修法：改写 `REACT_SYSTEM_PROMPT_JINJA2` 注入规划纪律 + 让 update_plan 对需要的 agent 生效。几乎零成本就能把"自主规划"从演示变成默认能力。

### 3.2 死代码增加误导
- `enhanced_prompt.go` 整文件（含 `ENHANCED_REACT_SYSTEM_PROMPT`）从未被引用（`node_chat_prompt.go:26` 硬编码用基础版）；`qwenCompatibleToolCallChecker` 也未被 builder 使用。应删除或择优合并。

### 3.3 MaxStep=30 写死 + 撞顶即放弃
- `builder.go:303` 写死 30；`ExecuteSequentially=true`（:298）把并行 tool_call 串行化、更快耗尽步数；撞顶后返回固定中文软提示直接放弃（`callback:99-121`），不是优雅降级。建议 MaxStep 按 agent 可配 + 撞顶时回灌"请基于现有信息总结"。

## 4. 🟡 P2 — 上下文 / 成本治理（高价值、中成本）

### 4.1 全程无 token 维度的上下文裁剪
- 对话流只按"轮"截断（默认 100 轮 `ConversationTurnsDefault`，或 `ShortMemoryPolicy.HistoryRound`），**没有 token 预算**（`agent_run_impl.go:642-654`）。长会话必撑爆上下文 / 成本失控。

### 4.2 工具中间结果全量累积回灌
- `GetByRunIDs` 返回 run 下全部消息，只过滤 verbose/knowledge（`agent_run_impl.go:266-273`）；function_call/tool_response 全量进上下文。sandbox `run_bash`/`read_file` 输出**原样全量**回灌（`node_tool_sandbox.go:89,123`）。
- 修法：接入 eino v0.9.6 自带的 `adk/middlewares/summarization` + `reduction`，并对工具输出加长度截断 + 历史 tool 结果摘要/丢弃。

## 6. 方向性建议（中长期）

### 6.1 自主规划引擎：DeepAgents 是正确方向，但作为独立项目灰度
- eino v0.9.6 自带 `adk/prebuilt/{deep,planexecute,supervisor}`。**DeepAgents (`adk/prebuilt/deep`)** 与本项目最契合：自带 `task` 子代理工具 + todos session + filesystem，正好替代手搓的 `update_plan` + sandbox 文件工具，实现真正"规划→子任务派发→上下文隔离→进度追踪"。
- 迁移成本中高、风险点明确：现有**流式 callback、中断恢复(Redis CPStore + 插件 OAuth)、returnDirectly** 三套定制逻辑与 `compose` callback 深度耦合（`callback_reply_chunk.go`、`runner.go:100-114`），需在 adk Runner/事件模型下重写验证。
- 建议：**保留 ReAct 作 fallback，新引擎灰度切换**，不要直接替换。短期先把 §3.1 的 prompt 驱动 update_plan 接上拿到 80% 价值。

### 6.2 技能系统：补全 + 结构化 + 版本化
- 补 plugin/knowledge 自动挂载（§2.2）；引用从正则文本升级为结构化关联表（保证引用完整性）；引用改"read_skill 激活时按需挂"真正贯彻渐进式披露；技能加 version，agent 发布时固化快照。

### 6.3 数据流强类型化（工作流，长期增量）
- 工作流全局 `map[string]any`（`workflow.go:37`）导致大量运行期断言/拷贝。长期在热点节点增量引入结构化类型 / schema 校验缓存。

## 7. 推荐整改顺序（按 价值/成本/风险）

| 阶段 | 任务 | 价值 | 成本 |
|---|---|---|---|
| **第一波（必做，低成本）** | ① 修 ExecuteConfig 锁拷贝(P0) ② GetByRunIDs status 过滤 ③ 技能 plugin/knowledge 挂载 + spaceID 校验 + status 过滤 | 极高(防崩溃/防错) | 低 |
| **第二波（高性价比）** | ④ prompt 驱动 update_plan 让自主规划生效 + 删死代码 ⑤ MaxStep 可配 + 撞顶优雅化 ⑥ 清理生产调试日志 | 高 | 低 |
| **第三波（治理）** | ⑦ token 预算上下文裁剪 + 工具输出截断/摘要(接 adk 中间件) ⑧ run 取消 + 客户端断连传播 ⑨ 幂等 ⑩ 合并重复 handler | 高 | 中 |
| **第四波（中长期）** | ⑪ DeepAgents 灰度(独立项目) ⑫ 技能版本快照 + 结构化引用 + L1 召回 ⑬ 工作流强类型化(增量) | 高 | 高 |
